# CTC — Causal Tracing Core (v2)

تنفيذ كامل لمواصفة "نواة التتبع المنطقي للمسببات" بعد معالجة الثغرات السبع المحددة في المراجعة (انظر `SPEC_v2.md` إن أُرفق، أو المحادثة الأصلية).

## بنية الملفات وربطها بأقسام المواصفة

| الملف | القسم المطابق | الوظيفة |
|---|---|---|
| `src/logic.rs` | القسم 2 | محرك JSON Logic حقيقي: تصريف (compile) مرة واحدة إلى AST، ثم تنفيذ دون تفسير نصوص وقت التشغيل |
| `src/rules.rs` | القسم 2 و5 | تحميل ملفات `.ctc.json`، فهرستها حسب trigger، إعادة التحميل الساخن |
| `src/proxy.rs` | القسم 1 و3 | الاعتراض الفعلي؛ **نمط Fire-and-Forget** يضمن صفر تأخير على مسار الاستجابة؛ أخذ العينات التكيفي المُصحح |
| `src/state.rs` | القسم 3.3 و4 | متعقب حالة LRU لآخر 5 طلبات لكل جلسة، للتتبع المسبب Backward Propagation |
| `src/storage.rs` | القسم 4 | SQLite لتسجيل الشذوذ فقط + سياسة احتفاظ 7 أيام + جدول تصادمات التجزئة |
| `src/metrics.rs` | القسم 5 | عدادات Prometheus بما فيها إضافات v2 (`ctc_samples_dropped_total`, `ctc_throttle_events_total`) |
| `src/admin.rs` | القسم 5 (مُصحح) | `/rules/reload` بتوقيع + audit log، `/trace/{id}` بتنقيح تلقائي |
| `src/resource_guard.rs` | القسم 6 (مُصحح) | مراقبة RSS الفعلية، هامش 80MB، تفعيل تقشف عند 70% |
| `src/cross_instance.rs` | القسم 7 (مُصحح) | تجزئة 64-بت (xxHash) + تأكيد كامل القيمة عند تطابق التجزئة |

## البناء والتشغيل

```bash
# محليًا (يتطلب Rust 1.75+ واتصال إنترنت لجلب الاعتماديات من crates.io)
cargo build --release
./target/release/ctc config/ctc.config.toml

# أو عبر Docker
docker build -t ctc-sidecar .
docker compose up
```

> ⚠️ **ملاحظة تنفيذ مهمة:** بيئة التطوير الحالية التي كُتب فيها هذا الكود لا تملك اتصالًا
> بالإنترنت (network egress معطّل)، لذلك **لم يُنفَّذ `cargo build` فعليًا هنا** ولا يمكن
> تأكيد نجاح الترجمة آليًا في هذه الجلسة. الكود مكتوب بعناية ومطابق لواجهات الإصدارات
> المُحددة في `Cargo.toml`، لكن يُنصح بتشغيل `cargo check` في بيئة متصلة بالإنترنت
> كخطوة أولى قبل النشر، ومعالجة أي أخطاء ترجمة طفيفة قد تظهر (تعارض إصدارات crates
> شائع في مشاريع Rust ويُحل عادة بتعديل رقم الإصدار في `Cargo.toml`).

```bash
# تشغيل الاختبارات الوحدوية (منطق JSON Logic + تصادم التجزئة)
cargo test
```

## اختبار سريع

```bash
# إعادة تحميل القواعد (يتطلب توقيع صحيح — القيمة الافتراضية للتطوير فقط)
SECRET_HASH=$(echo -n "change-me-in-production" | sha256sum | cut -d' ' -f1)
curl -X POST http://127.0.0.1:9091/rules/reload -H "x-ctc-signature: $SECRET_HASH"

# استرجاع تتبع طلب معين (مُنقّح افتراضيًا)
curl http://127.0.0.1:9091/trace/<request_id>

# استرجاع كامل غير منقّح (يتطلب صلاحية)
curl http://127.0.0.1:9091/trace/<request_id> -H "x-ctc-scope: trace:full"

# مقاييس Prometheus
curl http://127.0.0.1:9090/metrics
```

## القيود المعروفة صراحة (بدل الادعاء الزائد)

1. **مصادقة mTLS الفعلية غير مُطبّقة كودًا**: `admin.rs` يوفر تحقق HMAC مبسط كـ placeholder فقط. في الإنتاج، يجب نشر `admin_addr` خلف طبقة mTLS حقيقية (Istio/Linkerd mTLS أو reverse proxy بشهادات عميل) — هذا مسؤولية طبقة النشر (docker-compose/K8s) لا الكود التطبيقي وحده.
2. **توقيع `/rules/reload` مبسّط (SHA-256 لسر ثابت)** بدل توقيع Ed25519 حقيقي لكل حمولة — يكفي كنقطة انطلاق، ويُستبدل بسهولة في `verify_reload_signature()`.
3. **`redis-cross-instance` معطّلة افتراضيًا** (feature flag) لأنها تتطلب بنية تحتية Redis فعلية؛ فعّلها بـ `cargo build --features redis-cross-instance`.
4. **النطاق الوظيفي محدود بالقيود المُعلنة صراحة** في ملفات `.ctc.json` — لا يكتشف النظام أخطاء منطقية لا يمكن التعبير عنها كصيغة JSON Logic (كما وضّحت المراجعة السابقة).
5. **الأداء لم يُقاس فعليًا** (لا بيئة تشغيل متاحة هنا)؛ الأرقام في المواصفة (0.5 CPU / 80MB) أهداف تصميم يجب التحقق منها بـ load testing حقيقي قبل الاعتماد عليها في SLA.

## الترخيص وملاحظة أخيرة

هذا تنفيذ مرجعي (reference implementation) كامل البنية ومطابق لكل قسم في المواصفة v2، مُصمَّم ليكون نقطة انطلاق جاهزة للمراجعة والتدقيق الأمني قبل أي نشر إنتاجي فعلي — وليس بديلاً عن مراجعة أمنية مستقلة (particularly للمصادقة وmTLS المذكورين أعلاه).
